# Red Breacher

끝없이 몰려오는 적을 자동 전투로 돌파하는 모바일 탑다운 슈팅 RPG입니다. 오토 터렛·미사일 터렛·스텔스 폭격기·공격 헬기·융단폭격과 드론을 조합해 웨이브를 클리어하고, 가챠·장비 파츠·기지 업그레이드로 기체를 성장시키는 방치형 성장 루프를 구현했습니다.

3인 팀 프로젝트에서 전투·스킬 시스템, 적·보스, 튜토리얼, 플레이어 성장과 CSV 기반 밸런스 데이터 파이프라인을 담당했습니다.

## 핵심 구현

- **CSV ↔ ScriptableObject 데이터 파이프라인**: 유닛·무기·스킬·적·드론·장비·가챠 등 8종의 밸런스 데이터를 CSV로 관리하고, 에디터 임포터로 `ScriptableObject`와 동기화해 코드 수정 없이 밸런싱을 반복할 수 있도록 했습니다.
- **자동 스킬 전투**: 스킬별 쿨타임에 맞춰 자동 발동하며, 후보 적 주변의 밀집도를 비교해 광역 스킬의 중심점을 선택했습니다. 지속형 소환 스킬은 소환 종료 후 쿨타임을 시작해 중첩을 방지했습니다.
- **계정 기반 클라우드 세이브**: Google/Play Games 로그인과 Firestore를 연동하고, 로컬과 클라우드 저장 시각을 비교해 최신 데이터를 적용하는 방식으로 기기 변경 시에도 진행 데이터를 이어갈 수 있도록 했습니다.

## 저장소 공개 범위

이 저장소는 포트폴리오용 공개 버전입니다. 라이선스 보호와 보안 정보 노출 방지를 위해 Unity Asset Store 및 제3자 에셋 원본, 사운드·이미지·폰트·VFX 리소스, 외부 SDK 바이너리와 Firebase 환경 설정 파일을 전체 Git 기록에서 제외했습니다.

- 본 저장소만으로는 프로젝트를 바로 실행할 수 없습니다.
- 게임 로직, 데이터 처리, UI 제어 등 팀이 작성한 코드는 커밋 기록과 함께 유지했습니다.
- 원본 프로젝트 저장소는 비공개로 관리합니다.

## 주요 기술과 선택 이유

- **Unity 6 / C#**: 모바일 전투와 UI를 하나의 런타임에서 구현하고, 컴포넌트 기반으로 기능을 분리하기 위해 사용했습니다.
- **URP**: 모바일 환경에서 렌더링 품질과 성능 설정을 일관되게 관리하기 위해 선택했습니다.
- **CSV → ScriptableObject 데이터 흐름**: 밸런스 값을 코드와 분리하고, 기획 데이터 변경을 런타임에서 안정적으로 사용할 수 있도록 구성했습니다.
- **Firebase Authentication / Firestore**: 로그인과 사용자 진행 데이터 저장을 플랫폼 기능과 분리해 관리하기 위해 사용했습니다.
- **오브젝트 풀링**: 전투 중 반복 생성되는 투사체와 효과의 생성·해제 비용을 줄이기 위해 적용했습니다.

## AI 협업 개발 방식

Claude Code와 Unity MCP를 활용해 반복적인 에디터 작업과 정형화된 코드 작성을 보조했습니다.

- Unity MCP로 씬·프리팹·컴포넌트 작업, 스크립트 수정 후 컴파일 확인을 반복했습니다.
- CSV ↔ ScriptableObject 임포터처럼 패턴이 명확한 코드의 초안을 만들고, 스킬·적·튜토리얼 데이터가 늘어날 때 일관된 구조로 확장했습니다.
- 스킬 타게팅·쿨타임 처리와 클라우드 세이브 동기화는 AI와 설계안을 비교한 뒤, 지속형 소환 중첩과 동기화 실패 같은 예외 상황을 직접 점검해 반영했습니다.

## 안내

저장소에 포함되지 않은 에셋의 권리는 각 제작자와 라이선스 제공자에게 있습니다. 제외된 에셋이나 설정 파일의 재배포 요청에는 응답하지 않습니다.
